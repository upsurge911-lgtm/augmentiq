Executive summary

One product, two adapters — and the hierarchy matters

01
The Obsidian plugin is the product: it embeds the MCP server, owns the memory store, and writes the hash-chained audit log. Remove it and AugmentiQ has nowhere to store a memory.
02
The OpenClaw plugin is an adapter: six native tools proxying loopback HTTP to the vault server. It adds convenience, not capability.
03
The skill is a playbook, not a component: SKILL.md plus 22 references, running on seven hosts and any agentskills.io-compliant agent.
04
Three artifacts ship today. The first has passed live verification on a real vault; the other two are installed and loaded.
05
The enterprise backend (AugmentIQ+ over Docker) is deferred. It is not part of v0.1 and should not be sold as such.

Three layers, each with a different job

Host agent
Hermes, OpenClaw, Claude Desktop, Claude Code, Codex, Cursor, nanobot. Holds authority; decides what to store and confirms destructive actions.
Governance
The skill formats Context Records and enforces five immutable principles. The bridge exposes the same operations as native tools.
Vault server
Embedded MCP server on 127.0.0.1:3710. Bearer token, stateless HTTP, 10 tools. Owns the store and the audit chain.
Source: SKILL.md · references/mcp-integration.md · plugin/obsidian/src

A turn runs five steps, and only two of them write

Step 01
Recall
Query the store at session start. Lexical scoring in v0.1; embeddings are deferred.
Step 02
Reason
Deduce, induce, abduce over what was recalled. Silent — never narrated to the user.
Step 03
Respond
Answer informed by memory without announcing that memory was consulted.
Step 04
Record
Three to five typed memories per session: observation, conclusion, preference, instruction, summary.
Step 05
Consolidate
Weekly and non-destructive: surface duplicates, contradictions, and stale records for a human decision.

The security posture is narrow on purpose
127.0.0.1
the only interface the server binds
Transport is loopback HTTP with a bearer token compared in constant time. There is no remote listener and no cloud relay in the request path.
Data at rest is plain files inside .augmentiq/ in the vault: inspectable, backupable, and owned by the user rather than licensed from a vendor.
Every write appends a SHA-256 chained audit entry. Verification is a served operation, not a claim in a document.

Where AugmentiQ fits, and where it does not

Governed cloud memory
Audit trail without local custody. Fits teams that accept vendor-held storage for the guarantee of a managed timeline.
AugmentiQ
Local custody with an audit trail. The product's home: single-user, single-machine, compliance-adjacent.

Plain vault search
Local custody without audit. Good enough for retrieval; no classification, retention, or tamper evidence.
Ephemeral chat memory
Neither custody nor audit. Session-scoped recall; the default behaviour of most agents today.

Deployment is three steps and under five minutes

Install the vault
Obsidian → Community plugins → AugmentiQ → Enable. The plugin starts its server and generates a bearer token. Copy it from the ribbon.
Install the bridge
openclaw plugins install clawhub:upsurge/augmentiq, then paste the token. Config takes a literal string — SecretRefs do not resolve for plugin config.
Install the skill
Copy the package into the host's skills directory. On OpenClaw that is ~/.openclaw/workspace/skills/augmentiq/. Other hosts use their own path.

What a memory actually looks like on disk

Each record is a Context Record: a stable id, an event timestamp distinct from its recorded timestamp, a scope, a source, tags, and a classification. The audit reference ties it to the hash-chained timeline. Nothing is hidden in a binary index — the store is readable with a text editor and diffable in git. Classification is not cosmetic: a PII pattern match forces at least confidential before the record is written, and retention policy travels with the record rather than living in a separate rulebook.
