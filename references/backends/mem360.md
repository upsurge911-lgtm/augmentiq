# Backend: 5 backends supported in v0.1

---

## The 5 backends

1. **Obsidian** (`references/backends/obsidian.md`) — local-first
   Markdown, the most common individual choice
2. **mem0** (`references/backends/mem0.md`) — cloud memory layer,
   the most common team/enterprise choice
3. **ReMe** (`references/backends/reme.md`) — file-based, versioned,
   for compliance-conscious users
4. **Hermes native** (`references/backends/hermes_native.md`) — uses
   `~/.hermes/memories/MEMORY.md` + `USER.md`
5. **Custom** (`references/backends/custom.md`) — user-implemented
   adapter implementing 4 functions

**Removed from v0.1 scope (2026-07-17):**
- ~~Mem360 (360 Labs)~~ — target removed. The partnership thesis
  is no longer part of the v0.1 launch. If a different memory vendor
  becomes a relevant partner in the future, the per-backend reference
  template (`references/backends/<name>.md`) is reusable. The variable
  schema's `memory_backend` enum can be extended; for v0.1, it has
  only the 5 backends above.

---

## Why these 5 and not more

These are the 5 most-requested backends based on the kinds of users
AugmentIQ is built for:

- **Individuals** use **Obsidian** (most common) or **Hermes native**
- **Teams** use **mem0** (most common) or **Custom** (if they have
  an existing system)
- **Compliance-conscious users** use **ReMe** (versioning = built-in
  audit trail) or **Custom** (if they need a specific vector DB)
- **Power users** use **Custom** to plug in their own backend

The 5 cover ~95% of the realistic v0.1 user base. The remaining 5%
can use Custom (which has a 4-function contract; any backend with
an API can be wrapped).

---

## How the user picks

On `/augmentiq init`, the questionnaire asks (per `references/questionnaire.md`):
> "Which memory backend are you using?"
> "Where is it? (path or URL)"
> "How do you authenticate? (env var, OAuth, API key, none)"

The agent detects the backend from filesystem markers (Obsidian,
Hermes native) or env vars (mem0, ReMe) and confirms with the user
before writing the config. For Custom, the user provides the adapter
path.

## Compatibility matrix (with the 5 backends)

See `COMPATIBILITY.md` (todo 15) for the full host × backend matrix.
Short version: Obsidian + mem0 + ReMe + Hermes native + Custom all
work on Hermes (primary) and OpenClaw (secondary). The other host
agents work for Obsidian + mem0 + Custom; ReMe and Hermes native
require Hermes-specific code paths.
