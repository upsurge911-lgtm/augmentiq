# Legacy Ingest: local_files

---

## What this directive does

For sources with `source_category = local_files` (the user's local
filesystem, e.g., an Obsidian vault, a Documents folder, a
project-specific directory), the agent follows this directive to extract,
classify, transform, and load the data.

`local_files` is the **simplest** source category — no auth, no API rate
limits, no remote dependencies. The agent has direct filesystem access
(via its `terminal` tool or native file-read capability).

---

## Supported source types

| source_type | Typical content | Notes |
|---|---|---|
| `local_obsidian_vault` | Markdown files in Obsidian vault | `[[wikilinks]]`, YAML frontmatter, tags |
| `local_markdown_folder` | Generic Markdown files | No frontmatter required |
| `local_documents_folder` | Mixed: PDF, DOCX, XLSX, TXT, MD | Requires format detection |
| `local_project_folder` | Code, config, docs in a project | `.git`, `package.json`, `README.md`, etc. |
| `local_research_folder` | PDFs, papers, notes | Academic-style |
| `local_media_folder` | Images, audio, video (binary) | **Binary content is metadata-only** (filename, size, mtime); the agent cannot extract content from binary files in v0.1 |

---

## The directive

The agent follows this sequence for each `local_files` source.

### Phase 1: Discovery

1. Use the agent's `terminal` or native file-read tool to enumerate the
   source directory.
2. Build a file list: `[(path, size, mtime, type)]`.
3. Filter by user-defined include/exclude patterns
   (`legacy_sources[].include_patterns`, `legacy_sources[].exclude_patterns`).
4. Compute the actual `volume_gb` (sum of file sizes) and `item_count`.
5. If actual volume is much larger than the user's estimate (>2x), warn
   the user before proceeding.

### Phase 2: Per-file processing

For each file in the filtered list:

1. **Read the file** using the agent's file-read tool.
2. **Detect the format** from the file extension:
   - `.md`, `.markdown` → Markdown
   - `.txt` → Plain text
   - `.json`, `.yaml`, `.yml`, `.toml` → Structured
   - `.pdf` → PDF (requires `pymupdf` or similar; check agent capabilities)
   - `.docx`, `.xlsx` → Office (requires `python-docx`, `openpyxl`)
   - `.html`, `.htm` → HTML
   - Other extensions → unknown, flag for manual review
3. **Extract content** per the format:
   - Markdown: read body, parse YAML frontmatter
   - Plain text: read as-is
   - Structured: parse to dict, store as JSON in the record's `content`
   - PDF: extract text, store as text
   - Office: extract text + table contents
   - HTML: strip tags, store as text
   - Unknown: store `[binary: <filename>, <size> bytes, mtime <timestamp>]`
4. **Build the AugmentIQ Context Record**:
   - `id`: `augmentiq:<uuid>`
   - `timestamp`: file's mtime (not the current time — historical accuracy)
   - `scope`: from config
   - `source`: `local_files:<source_id>:<relative_path>`
   - `content`: extracted text
   - `tags`: from YAML frontmatter (if Markdown), plus user-defined tags
   - `classification`: from `legacy_sources[].classification_default`, then
     PII auto-upgrade
   - `retention_policy`: from `retention_period_days[classification]`
   - `audit_ref`: the timeline entry for this batch
   - `provenance`: `{ source_system: "local_files", path: <relative>, mtime: <iso> }`
   - `pii_patterns`: from PII scan (per `references/ingest/pii-patterns.md`)
   - `embedding`: generated by the agent's native embedding model

### Phase 3: Write to memory backend

1. For Obsidian backend: write the file to
   `<vault>/<classification>/<relative_path>` (preserving folder structure)
   with the AugmentIQ Context Record metadata in YAML frontmatter.
2. For mem0 / ReMe backends: write the record via the backend's
   native API.
3. For Hermes MEMORY.md backend: append a section with the record's
   metadata + content.

### Phase 4: Batch logging

Per the batch protocol (`references/ingest/batch_protocol.md`):
1. Log the batch entry to the timeline.
2. Update `legacy_sources[].items_processed`, `items_remaining`,
   `last_batch_timestamp`, `next_batch_timestamp`,
   `estimated_completion_date`.

## Per-source configuration

The user configures the source via the questionnaire or
`/augmentiq reconfigure`:

```yaml
legacy_sources:
  - source_id: "obsidian-personal"
    source_type: "local_obsidian_vault"
    source_category: "local_files"
    location: "~/Documents/Obsidian Vault"  # absolute or ~-relative path
    include_patterns: ["**/*.md"]            # glob patterns to include
    exclude_patterns: ["**/.trash/**", "**/node_modules/**"]  # glob patterns to exclude
    classification_default: "internal"
    transfer_strategy: "one_shot"            # or "nightly_batches"
    batch_size: "medium_1000"               # for nightly_batches
    estimated_completion_date: "2026-07-17" # shown for confirmation
```

## The "preserve folder structure" decision

For Obsidian backends, the user can choose to:

- **Preserve folder structure**: the record's path inside the vault mirrors
  the source path. Easy to navigate, but the vault can get cluttered with
  the legacy folder structure.
- **Flatten**: all records go to a single folder, tagged with their original
  path. Easier to scan, loses folder hierarchy.
- **Re-classify by folder**: use the source folder to set the record's
  classification (e.g., `~/Documents/Obsidian Vault/Confidential/...` →
  classification = `confidential`).

**Default:** preserve folder structure. The user can override.

---

## What this directive does NOT do

- It does not follow symlinks by default (security). The user can opt in
  to following symlinks via the config.
- It does not recurse into mounted filesystems (e.g., `~/mnt/network`).
  The user can opt in via the config.
- It does not watch for changes during ingest (the ingest is one-shot
  or in batches; not a live sync).
- It does not handle file-locking. If the file is being written to during
  the ingest, the read may get a partial state. The agent retries on
  partial state (with backoff), but a live process may require the user
  to stop it first.
- It does not transcribe audio/video content. Binary media is metadata-only
  in v0.1. Future: integrate Whisper for audio, vision models for video.

---

## Performance

- Local reads are fast. The throughput coefficient is 5.0 GB/hr
  (per `estimator.md`).
- The bottleneck is usually the embedding generation (the agent's native
  embedding model) and the write to the memory backend.
- For Obsidian backends, writing to a vault on the same filesystem
  is fast (no API overhead). For cloud backends, network latency applies.

## Example session

User runs `/augmentiq ingest --source=obsidian-personal`:

1. Agent runs `find ~/Documents/Obsidian\ Vault -name "*.md" -not -path "*/.trash/*"`.
2. Returns 2,847 files, 1.8 GB total, oldest mtime 2019-04-12.
3. Agent computes estimate: 0.4 hours for volume + 0.28 hours for items
   + 0.09 hours overhead = 0.77 hours, parallel = 0.39 hours wall-clock.
4. Agent shows the strategy recommendation:
   ```
   Source: obsidian-personal
   Volume: 1.8 GB, 2,847 items
   Strategy: one_shot (estimated 23 minutes wall-clock)
   Classification default: internal
   ```

5. **Confirmation prompt** (per Principle 4):
   ```
   About to ingest 2,847 files from ~/Documents/Obsidian Vault.
   Strategy: one_shot
   Estimated: 23 minutes
   Classification: internal (auto-upgraded if PII detected)

   Proceed? [y/n]
   ```
6. On confirm: agent starts processing.
7. After 23 minutes: agent reports
   `2,847 items succeeded, 0 failed, 18 auto-upgraded to confidential (PII detected)`.
8. Source `ingest_status` transitions to `completed`.
